# Ghillie Ops - ARCHITECTURE

This document is binding for every builder. It describes what exists (A1 Foundation) and the contracts later aspects plug into. SPEC.md holds the requirements; this file holds the structure.

## 1. Principles

- One page, ES modules, no build step. Libraries are vendored under `vendor/` and resolved through the import map in `index.html`. No request leaves `localhost` at runtime, except the PeerJS broker in multiplayer (A11).
- Fixed 60 Hz simulation (`TICK = 1/60` s) with interpolated rendering. All gameplay state changes happen in tick systems; frame systems only present state. All timings are in seconds.
- Host-authoritative gameplay (A7 on): every soldier (human or bot) is driven by a per-tick command, so the same simulation code runs on the host, in guest prediction and in accelerated selftests.
- Modules are factories (`createX(...)`) that receive what they need. The shared engine object is `ctx` (section 4). No globals except `window.__GO`.
- Self-checks live next to the code: each module registers its selftests at module scope. Silent on success, `module + file:line + reason` on failure.
- Code rules of SPEC section 9 apply everywhere: no comments, no emojis, no speculative code. `node tools/check.mjs` enforces the mechanical part.

## 3. Running

- Double-click `Start.bat`. It probes `http://127.0.0.1:8790/__ghillieops` (signature `{"app":"ghillie-ops"}`). If our server answers it only opens Chrome; if another program listens on 8790 it says so; otherwise it starts `node server.js` hidden and waits. `GHILLIE_NO_BROWSER=1` skips opening Chrome (used for headless tests of Start.bat).
- `server.js`: GET/HEAD only, `Cache-Control: no-cache` with ETag (always revalidated, 304 when unchanged, never stale), `no-store` for errors and the signature, path traversal blocked (403), MIME for html/js/mjs/css/json/map/txt/md/wasm/glb/gltf/bin/ktx2/png/jpg/webp/svg/woff2/ogg/mp3/wav. Binds to 127.0.0.1 only (no firewall prompt). `GHILLIE_PORT` overrides the port.

Query flags (parsed in `core/flags.js`, invalid values fall back to defaults and print one `[flags]` warning each):

| flag | values | default | consumer |
|---|---|---|---|
| view | world, test, weapons, later characters, game | world (A9: game) | main.js view registry |
| mode | normal, team, conquer | null | A9 match setup |
| autostart | 1/0 | 0 | skips the start overlay (A9: skips the menu) |
| bench | 1/0 | 0 | A12 scripted benchmark |
| seed | uint32 | random | ctx.rng |
| netsim | latencyMs,jitterMs,lossPercent | null | A11 net/netsim.js |
| selftest | 1/0 | 0 | runs every registered check after boot |
| preset | medium, high, ultra | high | initial render preset (runtime changes use `render.setPreset`) |
| scale | 0.25..2 | 1 | render scale |

## 4. Boot and the ctx object

`src/main.js`:
1. Parses flags, creates the loading screen and pause overlay, registers the `boot` state provider at module scope (so `__GO.state().boot.error` exists even when boot throws), starts a `PerformanceObserver` that records every resource request to another origin.
2. Creates `ctx.rng`, `ctx.loop`, `ctx.render`, `ctx.gl`, `ctx.perf`, `ctx.input`, `ctx.assets`, registers the engine `__GO` API, reads the keyboard layout (section 6).
3. Imports the view module from `VIEWS[flags.view]` and calls `createView(ctx)`. A view starts all its loads synchronously before its first `await`, so the asset tracker knows the whole job list; only then does the loading bar start tracking. The view builds its scene and returns `{ scene, camera, restoreGpu, ... }`.
4. Creates `ctx.post` for the view scene/camera, compiles all shaders (`compileAsync`) and renders one warm-up frame while the loading screen still shows "Compiling shaders", verifies program link status.
5. Adds the engine systems (`input` endTick at tick order 1000, `render` at frame order 1000, shader verification at 1001), wires pause and context loss, starts the rAF driver, hides the loading screen, sets `boot.ready`, runs the selftest if `?selftest=1`.

Loading bar: 2% "Starting engine" until the view module is imported, then `5% + 85% * assets.fraction()` with the status `assets.status()` ("Loading textures 1/3", "Loading models 0/2"), 92% "Compiling shaders", 100%. `fraction()` is weighted by bytes (loaded/total from the loader progress events; a job of unknown size weighs an estimate: 4 MB per model, 2 MB per texture), is 0 for an empty tracker, and reaches 1 only when every job finished. The bar never moves backwards.

rAF driver per frame: `perf.begin()`, `render.beginFrame()` (resize/DPR sync, renderer.info reset), `loop.advance(dt)`, `perf.end()`.

| ctx field | created by | purpose |
|---|---|---|
| flags, boot | main | parsed flags, boot status (`ready view seed error contextLost`) |
| rng | core/rng | `next() range(a,b) int(a,b) pick(list) stream(name)`; use `ctx.rng.stream('bots')` etc. so modules do not disturb each other |
| loop | core/loop | `addTick(name, fn(dt), order)`, `addFrame(name, fn(alpha, dt), order)`, `remove(name)`, `step(n)`, `paused`, `tick`, `simTime`, `alpha` |
| render | render/renderer | `renderer gl canvas preset presetName scale width height gpu onResize(fn) onPreset(fn) setScale(s) setPreset(name) beginFrame() verifyPrograms()`; module exports `PRESETS NEAR FAR verticalFov` |
| perf | core/perf | `begin end reset samples summary gpuTimer` |
| input | core/input | `down(a) pressed(a) released(a) look() endTick() lock() onLockChange(fn) setLayout(map) rows() heldCodes() state moveEvent` |
| assets | core/assets | `model(name, size) gltf(url, size, name?) texture(url, {srgb, repeat}) fraction() pending() status() setAnisotropy(n) placeholders progress` |
| view | views/* | `{ scene, camera, restoreGpu() }` plus view specific handles |
| post | render/post | `{ composer, passes: {scene, ao, hdr, aa}, effects: {bloom, tone, smaa}, render(dt) }` |
| later | A5+ | `world`, `veg`, `game`, `chars`, `bots`, `ui`, `audio`, `net` (section 7) |

Graphics presets at runtime (`render.setPreset(name)`, `__GO.setPreset(name)`; Settings in A9 call it directly, no reload): `onPreset(fn)` listeners are called immediately with the current preset and again on every change. Current listeners: post (N8AO quality and half resolution), the sun (shadow map size, shadow distance, filter radius), assets (anisotropy of every loaded texture, re-uploaded). Every later module that reads a PRESETS field registers an `onPreset` listener instead of reading the preset once. `shadowCascades` must have the same value in every preset (it is compiled into every lit shader, section 7); everything else may change at runtime.

WebGL context loss: `main.js` pauses and shows "Graphics reset / Restoring graphics" on `webglcontextlost` (clicks cannot resume while the context is lost); three re-creates its GL state on `webglcontextrestored`, then `ctx.view.restoreGpu()` rebuilds GPU-generated content (PMREM environment, baked render targets) and the overlay offers "Click to resume". `perf` re-acquires its timer extension. A `restoreGpu` drops references to GPU objects created before the loss instead of disposing them (disposing them makes Chrome print `object does not belong to this context` warnings).

## 5. Loop, interpolation, pause

- `loop.advance(dt)` clamps dt to 0.25 s, accumulates, runs at most 8 ticks per frame (backlog dropped, no spiral of death), sets `alpha = acc / TICK`, then runs every frame system. A throwing system is reported once (deduplicated `[loop/<name>] file:line - reason`) and never stops the others.
- Interpolation contract: a simulated object keeps `prev` and `curr` state; at the start of its tick it copies `curr` to `prev`, then integrates `curr`. Frame systems render `lerp(prev, curr, alpha)` (slerp for rotations). Mouse look is applied at frame rate (lowest latency), the sim reads the current view angles at each tick. The test view camera (`moveCamera`, `placeCamera`) is the reference implementation: systems are plain functions of their state and inputs, so selftests can run them on a private loop.
- Accelerated simulation: selftests and benchmarks call `loop.step(n)` of a private `createLoop()` or dedicated headless tick functions directly; never rely on rAF for simulated time and never step the live loop from a check (section 9).
- Tick order (lower runs first): 10 player commands (local input -> command), 20 soldier movement (player + bots), 30 weapons and grenades, 40 bots brain (staggered), 50 damage/spawn/director, 60 mode rules and round timer, 70 net send, 1000 input endTick.
- Frame order: 10 camera, 20 characters/animation, 30 vegetation and wind, 40 effects (tracers, particles, decals), 50 audio listener and voices, 60 HUD, 1000 render, 1001 shader verification.
- Pause: losing pointer lock (Esc) or hiding the tab pauses (`loop.paused = true`, overlay with key bindings). Clicking the overlay requests pointer lock and resumes on success; a refused lock keeps the game paused with a message. Without `?autostart=1` the session starts paused ("Click to start"). In multiplayer (A11) the pause overlay must not freeze the simulation: the net layer keeps ticking and only local input is suppressed.
- Hidden-tab driver (A11): browsers stop requestAnimationFrame in hidden or occluded tabs, so a host would stop simulating. A11 adds it: `net` starts a dedicated Worker whose only job is a 60 Hz `setInterval` that posts a message (worker timers are not throttled like main-thread timers). While `document.hidden` or when no rAF arrived for 100 ms, the main thread handles each message by running the ticks that are due (the same accumulator as `loop.advance`, frame systems skipped, nothing rendered). Ticks, net sends and bot brains therefore continue at 60 Hz in a hidden host tab; the rAF driver takes over again as soon as frames arrive, and both drivers share the accumulator so no tick runs twice.

## 6. Input

- Default bindings (action -> codes, `KeyboardEvent.code`, `Mouse0..2`, `WheelUp/WheelDown` edge only) and action labels live in `core/input.js`; the pause overlay lists `input.rows()` (`[label, [key caps]]`).
- Keyboard layout: `readLayout()` uses `navigator.keyboard.getLayoutMap()` (falls back to the defaults when unavailable or refused); `input.setLayout(map)` resolves the bindings. Movement and other positional keys (WASD, Space, Shift, digits) stay on their physical codes. Letter mnemonics (crouch C, prone Z, reload R) move to the physical code that types that letter on the active layout (German QWERTZ: prone -> `KeyY`, the key labeled Z), unless that code is already a positional binding (then the default code stays). Key caps come from the layout map (the real printed letter), named keys from a fixed table. main.js re-reads the layout every time the pause overlay opens, so a layout switch is picked up before the player resumes.
- `pressed/released` are edges that stay visible until the next tick consumed them (`endTick` at order 1000), so no press is lost at any frame rate.
- Pointer lock uses `requestPointerLock({ unadjustedMovement: true })` (raw mouse, no OS acceleration) with a fallback to the normal lock when unsupported. Mouse deltas come from `pointerrawupdate` where available and only accumulate while locked. `input.look()` returns and clears the accumulated counts; sensitivity is applied by the consumer (A7 player, A9 settings). Releasing the lock is done by the browser (Esc); the game never exits the lock itself.
- Blur, tab hide, lock loss and a layout change release all held keys.

## 7. Modules of later aspects (contracts)

Each module below registers its selftests and `__GO` commands as described in section 9.

### World and terrain (A5) - `src/world/`
- `layout.js`: the single source of map data for the game and the bake tool: MAP (2048 m, 1025 height samples at 2 m), HEIGHT window (-20..280 m in 16 bit), HORIZON (16 km at 32 m), RIVER polyline `[x, z, width, level]`, ROADS, BRIDGE, BASES (`red`, `blue`, `A` farm, `B` radio tower, `C` village, `D` quarry), PADS, QUARRY, HILL, `trenchLine()`, BUNKERS, the 8 BOOKMARKS (`from` and `to` as x, height above ground, z), `bookmarkPose`, and CATALOG (kind, size and sink fraction of every placed model).
- `tools/bake_world.mjs` (`node tools/bake_world.mjs`, about 25 s, deterministic): domain-warped ridged fBm hills (HEIGHT window -20..480 m, median slope about 14 degrees, ridgelines and valleys across the whole 2 km map, rising to mountains at the horizon) plus the designed features (river valley with a preserved channel and bed profile, small blended base and village pads, landmark sites chosen on natural shoulders and summits, radio hill, hillside quarry with benches, trench line along a ridge, terrain-aware A* roads with cut and fill, yard and dirt masks around buildings), then `assets/world/height.bin` (u16), `mask.bin` (RGBA8 at 2 m: road/dirt, rock, riverbed/wet, forest), `grass.bin` (R8 grass density), `horizon.bin` (u16, 513 x 513 at 32 m, same height function) and `world.json` (river polyline and every placement as `[x, y, z, yaw, scale]` per model: trees, bushes, ferns, rocks, logs, stumps, bridge, bunkers, sandbag trench, base compounds, farm, tower hill, village, quarry).
- `terrain.js`: 16 x 16 chunks of 128 m with four LODs (2, 4, 8, 16 m cells, skirts instead of stitching, vertex normals from the full resolution map so lighting does not pop); beyond 230 m chunks are replaced by 256 m tier meshes (4 m cells) and beyond 520 m by 512 m tier meshes (8 m cells), so the terrain costs about 90 instead of 270 draw calls, two horizon rings (32 m and 128 m cells out to 8 km, with skirts at their inner holes), one shared splat material (five layers, albedo + normal each, KTX2): grass, forest floor, rock (triplanar, driven by slope), dirt/road/wet banks, riverbed gravel; hex (stochastic three-sample) tiling for every layer so no texture repeat is visible, the grass layer takes its colour from the shared meadow palette (`meadowGlsl`, also used by the grass blades) modulated by the texture luminance, macro colour variation, detail normals fade with distance and the layer stack is replaced by the average layer colours beyond 750 m; mask and grass density fade out at the map edge. API: `heightAt` (exactly the rendered LOD0 triangulation), `normalAt`, `slopeAt`, `maskAt`, `grassAt`, `surfaceAt`, `raycast` (grid walk over the heightfield triangles, no mesh BVH needed because the data is a regular grid), `update(camera)` for LOD selection, `uniforms` and `terrainGlsl` (triangle-exact height lookup for shaders).
- `water.js`: river ribbon with per-vertex flow coordinates (distance along the river, across offset, tangent) so ripples travel along the river; custom ShaderMaterial: analytic refraction of the bed (terrain height texture and the riverbed albedo, Beer absorption), planar reflection of terrain, tree proxies, bridge and sky rendered from a mirrored camera into a 0.4x half-float target (layer `REFLECTION_LAYER`, global clipping plane, only when river is on screen within 320 m), Fresnel, roughness that widens with distance (no sparkle), shoreline foam, soft shore alpha. `depthAt`, `levelAt` for gameplay.
- `collision.js`: every placed model carries its own collision proxies as nodes whose name starts with `col_` (boxes, cylinders, convex hulls built in Blender); `createCollision` merges all proxies of all placements (about 330k triangles) into one `MeshBVH` (`indirect`, per-triangle surface ids from the model name via `veg/models.surfaceOf`). API: `raycast(origin, dir, far) -> { point, normal, distance, surface, kind: 'terrain'|'object' } | null` (terrain heightfield, objects BVH, water surface for rays that end in the river), `groundAt(x, fromY, z)` (highest walkable surface below a point: terrain, bridge deck, floors), `capsuleCollide({ start, end, radius }) -> Vector3` push-out against objects and terrain. Bridge, walls, towers, rocks, trunks, crates, sandbags are all in it; there are no invisible walls.
- `nav.js`: 2 m grid over the whole map (blocked: slope above 0.62, deep water, any collision triangle whose height range overlaps walking height; the bridge deck is forced open), A* with 8 neighbours and a binary heap. API: `walkable(x, z)`, `nearest(x, z)`, `path(ax, az, bx, bz) -> [{ x, z }] | null`, `cost`, `openFraction`. Bots add door-level navigation in A8.
- Bases: red (north-west end) and blue (south-east end) compounds with HQ, watch towers, tents, crates, barrels, hesco and sandbag perimeters, flag poles whose cloth is tinted per instance (`veg/props.flagTeam`); Conquer bases A farm, B radio tower hill, C village, D quarry each carry a neutral flag and meaningful cover; trench and bunker line north of the river. The game view (`views/world.js`) owns the world; the menu background (A9) reuses it.

### Rendering, lighting, vegetation (A6) - `src/render/`, `src/veg/`
- Depth: the renderer runs with a reversed float depth buffer (`reversedDepthBuffer: true`, EXT_clip_control; the composer depth textures are `FloatType`). Cameras use `NEAR = 0.1` and `FAR = 12000` m (8 km horizon plus margin). Precision is effectively constant over distance: the renderer selftest separates two quads 0.3 m apart at 2 km. Fullscreen passes must not depth test (or must write `gl_Position.z = 0.0` under `USE_REVERSED_DEPTH_BUFFER`, as the sky does), because the reversed depth buffer clears to 0.
- Sun and shadows (`render/sun.js`): `createSun(render, color, intensity)` returns a three `SunLight` (three's native sun path, no per-material setup) whose shadow is our `CascadedShadow`: `PRESETS.*.shadowCascades` (4) cascades packed into a 2x2 atlas of `shadowMapSize` tiles, practical split scheme (`lambda 0.92`, log part from 1 m) up to `shadowFar` (350 m; full shadow to 324 m, faded at the end), cascades overlap by 10% and blend, each cascade is the minimal bounding sphere of its frustum slice, snapped to its texel grid (no shimmer while moving), casters up to one shadow distance towards the sun are included. At 3840x1080 (127 deg Hor+ horizontal FOV) on High the first cascade covers 0.1-11 m at 2.2 cm per texel (Ultra 1.1 cm, Medium 3.0 cm); the far cascade is 71 cm (High) at 89-350 m. Normal offset bias is scaled per cascade by its texel size (`normalBias` is in texels); `bias` is a small positive constant (reversed depth). sun.js patches three's `shadowmap_pars_fragment` chunk at import (cascade count define and per-cascade normal offset) and reports an error if the pinned three changes that chunk; every view that lights with the sun uses `createSun`. A6 may add contact-hardening (PCSS) filtering in the same chunk; the cascade layout stays.
- `render/lighting.js` (A6): sky (three `Sky` with the reversed-depth and horizon-to-fog patch and the sky radiance cap used in the test view), the sun from `createSun`, PMREM environment from the sky, exposure, time of day. Fog is not plain `FogExp2`: A6 replaces it with height fog plus aerial perspective, in the scene materials through a shared fog chunk: density falls off exponentially with altitude (dense in valleys, thin on hilltops), in-scattered colour is the sky colour in the view direction near the horizon plus a sun-direction Mie lobe (warm towards the sun), and the far terrain and horizon are blended into the same function, so the horizon never shows a hard terrain/sky line. The sky shader uses the same function for its lowest band.
- Bloom and the sun: bloom is threshold-free (the whole HDR image is blurred and added at low intensity, so no luminance contours form), its input is capped at a luminance of 8 before the first downsample (`post.js` patches pmndrs' luminance shader, checked by a selftest), and the sky radiance is capped at a luminance of 40 so the half-float scene buffer never overflows. Very bright speculars therefore cannot produce rings or hue fringes.
- Anti-aliasing and specular aliasing: SMAA (high) is the last pass now (`post.passes.aa`, with dithering against 8-bit banding). A6 adds specular anti-aliasing in the materials (normal-variance roughness widening, Toksvig style, for normal-mapped PBR materials and foliage) and replaces SMAA with a temporal AA pass in the same slot (jittered projection via `camera.setViewOffset`, history reprojection with velocity from the previous view-projection matrix and neighbourhood clamping) once grass and specular shimmer demand it; the viewmodel pass is rendered without jitter.
- `render/post.js` extension points: insert passes with `post.composer.addPass(pass, post.composer.passes.indexOf(post.passes.hdr))` (for example the first-person viewmodel pass from A3/A7, which renders a separate scene with its own camera and FOV after AO and before bloom/tone mapping); color grading is added as an effect in the hdr pass; AA stays last.
- `renderer.PRESETS` is the single quality table; A6 extends it (grass density and distance, AO quality, draw distances) and every consumer listens with `render.onPreset`. Settings (A9) choose the preset name and render scale.
- `veg/grass.js`: GPU-instanced grass in chunks around the camera, wind as traveling gusts, an interaction texture (top-down) written from soldier positions and grenade events for bending and flattening, distance fade into the terrain color. `veg/trees.js`: instanced species with LOD/impostors and wind sway.

### As built in S2: rendering, vegetation and the world view
- `render/lighting.js`: `createLighting(ctx, scene)` builds the sky (three `Sky` with the reversed-depth patch, visible sky dimmed by `SKY_SCALE` and desaturated, clouds), the `createSun` cascaded sun, a PMREM environment from an unpatched twin sky plus a ground bounce disc, exposure and `scene.environmentIntensity` (0.55), `setTime(hours)` (rebuilds sun, environment, fog) and `update(camera, simTime)`. Height fog is a patch of three's fog chunks (`fog_pars_vertex/fog_vertex/fog_pars_fragment/fog_fragment`, verified at import): per-fragment analytic integral of an exponential height density along the view ray (`fogHeight`: reference altitude and falloff), colour = scene fog colour (sky horizon radiance) plus a sun-direction lobe (`fogSunDir`, `fogSunColor`); the extra uniforms are added by `injectFog(shader)`, which is also installed as the default `Material.prototype.onBeforeCompile`, so every material that does not define its own hook gets them. Custom `onBeforeCompile` hooks must call `injectFog(shader)`.
- Post (`render/post.js`): the tone mapper is Khronos PBR Neutral (hue preserving; ACES turned saturated greens yellow and saturated blue sky cyan); order inside the HDR pass is bloom, tone mapping, saturation (+0.1), contrast (+0.07), vignette. Colour effects must stay after tone mapping: `HueSaturationEffect` and `BrightnessContrastEffect` clamp their input to 0..1, in front of the tone mapper they flatten every HDR value to one grey level.
- `veg/models.js`: `loadModels(assets, names)` loads GLBs and converts them to plain data: visuals (`{ lod, geometry, material }`, geometry baked to float attributes in the model root's space, LOD taken from a `...lodN` node name), one merged collider geometry from the `col_` nodes, foliage materials (`Leaf_*`) turned into alpha-tested double sided materials, structure/prop albedo trimmed by 0.6 (the Poly Haven and ambientCG albedos are too bright for this exposure). Model conventions: root node named like the file, origin on the floor, +Z (Blender -Y) is the front, meshes `<Name>_lod0..2`, colliders `col_*`.
- `veg/props.js`: rocks, logs and props (512 m cells) are one `InstancedMesh` per model, material and cell, frustum culled by three and hidden beyond a per-kind distance. Structures (256 m cells) are merged: every placement of every structure model is baked into world-space geometry and drawn as one plain `Mesh` per cell and distinct material (materials are equal when name, colour, roughness, metalness, sidedness and the texture bytes match, so `M_frame`, `M_steel` and the other shared sets of all houses, towers and huts become one draw call per cell); `FlagPole` (per-instance flag colour) and `StoneBridge` (water reflection layer) stay instanced. Beyond the detail range only the three largest materials of a cell draw, and shadows are cast inside a per-kind range (rock 45 m, prop 30 m, structure 130 m, small materials 60 m, all measured from the cell edge). Draw calls are the main CPU cost of the world: the village view went from 936 to 575 calls per frame (shadow cascades included).
- `veg/trees.js` (S2-R): every tree is a real scanned model (`OakTree` = Poly Haven "Island Tree 01", `BeechTree` = "Jacaranda Tree", split with the oak placements; `SpruceTree` = "Fir Tree 01"; `BirchTree` = Objaverse "Birch Tree", CC-BY; `BushA` = Objaverse "Photorealistic Bush", CC-BY), converted by `tools/blender/bl_r_tree.py`, `bl_r_cards.py`, `bl_r_asm.py`, `bl_r_imp.py` and `tools/blender/tree_atlas.py`: the scan is scaled to height, its leaf islands are clustered (k-means over leaf centroids, 150 clusters per tree), every cluster is rendered from the original geometry as an albedo plus view depth tile (two orthographic views per cluster) into a leaf atlas (colour dilated into transparent texels, depth turned into ambient occlusion), and the model is rebuilt as decimated trunk and branch meshes (`<Name>_s_lod0..2`, original bark textures) plus leaf cluster quads (`<Name>_c_lod0..2`, material `Leaf_<Name>`, vertex colour AO, normals bent outward from the crown centre). LOD0 (to 34 m) 14k trunk triangles plus 600 card triangles, LOD1 (to 105 m) 3.5k plus 180, LOD2 (to 380 m) 700 plus 270 (instanced meshes, view-cone filtered on the CPU: list rebuilt every 3 m or 17 degrees of turning, cone margin 31 degrees), beyond 380 m a hemi-octahedral impostor (8 x 8 views baked from the full original mesh: albedo with AO, world normal, KTX2 in `assets/textures/trees/<Name>_imp_a|n.ktx2`, registry `impostors.json`) drawn as one instanced quad per tree for every tree of the map without any distance cut-off. The impostor vertex shader builds a camera facing billboard around the baked centre and picks the three nearest frames of the octahedral map, the fragment shader blends albedo and normal of the three frames (alpha weighted), rotates the baked normal by the instance yaw and lights it with the same sun, cascade shadow and sky ambient as the meshes. All LODs share the dither cross-fade (screen space, distance driven) and the same leaf translucency (back lit transmission term patched into `lights_physical_pars_fragment`). Shadows: LOD0 casts, far trees cast through alpha-tested impostor proxies (30 to 360 m) whose depth material shifts the proxy 3 m away from the sun; the water reflection draws impostor proxies on its own layer. Wind sway in the vertex shader, leaf flutter on `Leaf_*`.
- `veg/grass.js` (S2-R): seven GPU-generated tiers of Blender-made tufts (`GrassTuft0..6`, `tools/blender/bl_grass.py`) drawn with `InstancedBufferGeometry` and `gl_InstanceID`, from 0 to 3300 m (spacing 0.27, 0.55, 1.2, 2.6, 6, 13, 28 m; each tier fades in and out by blade height inside an overlap band, instances outside the view cone are rejected before any texture fetch, no CPU work per frame beyond uniforms). A tuft is a bunch of curved, tapered, twisted blades with a V cross section and rounded normals (fine meadow grass, broad blades, dry straw blades, low leaves, and in the near tuft seed stalks with seed heads, clover leaves and wild flowers). Vertex data: `uv.x` signed half width in centimetres, `uv.y` height along the blade, `color` = random id, rare-species presence threshold, species code (0 fine, 1 broad, 2 dry, 3 stalk, 4 seed head, 5 clover, 6 flower, 7 flower stalk), azimuth of the blade side vector. The vertex shader derives a world anchored jittered cell, reads the terrain height texture and grass density map, hides rare species by field noise, scales height by density, widens every blade so it covers at least half a pixel on each side (`uPx` = half the drawing buffer width, so the blades of the far tiers stay stable at any resolution), bends with the wind gusts, blade flutter and the interaction field, and colours blades from the shared meadow palette (`meadowTint`, `meadowDry`, `meadowMean` in `world/terrain.js`: live green, straw, root to tip gradient, per blade variation, blend into the terrain mean colour beyond 150 m). Lighting: `MeshLambertMaterial` with sun cascades, sky ambient, base ambient occlusion and a back lit translucency term (patched into `lights_lambert_pars_fragment`, checked at import). Interaction field: a 128 x 128 RGBA8 texture around the camera (0.5 m texels, toroidal): `grass.actor(id, x, z, vx, vz, radius)` makes blades lean away (soldiers, bots), `grass.flatten(x, z, radius, strength)` flattens them for a few seconds (grenades), both decay over time.
- `views/world.js`: builds everything and publishes it as `ctx.world = { scene, camera, cam, lighting, terrain, water, props, vegetation, grass, collision, nav, models, data, placements }`; free-fly (WASD, Space/C vertical, Shift fast) and walk camera (F toggles; ground-follow with `collision.groundAt` and capsule push-out, 1.7 m eye, C crouches; the real controller is S3), B cycles the map bookmarks, soft limit 120 m beyond the map edge. `__GO`: `bookmark(name|index)`, `mode('fly'|'walk')`, `teleport(x, y, z, yaw?, pitch?)`, `setTime(hours)`, `flatten(x, z, radius)`; state key `view` reports camera, bookmarks, tree LOD counts, collision triangles, nav openness.

## 9. Selftest and debug conventions

- Register at module scope: `register('<module id>', '<what is checked>', async ctx => { ... assert(cond, 'reason with values'); })`.
- A check restores every state it touches and leaves no trace: it never steps the live loop (systems are run on a private `createLoop()` with a private input, see `views/test`), uses private instances for anything that caches or counts (`core/assets` creates its own `createAssets()` for the failure paths, so the live cache, job list and error counter stay untouched), and switches presets or time of day only inside `try/finally` that switches back. It must not print on success, must not trigger console output or failed network requests (failure paths use `data:` URLs and intercept `console.error/warn`), and finishes within 30 s. Checks run sequentially with the live `ctx`. `?selftest=1` followed by any number of `__GO.selftest()` calls gives the same result.
- Failure output: `[selftest] FAIL <module> "<name>" at <file:line> - <reason>`; runtime errors outside checks use `report(module, err)`: `[<module>] <file:line> - <reason>`, printed once per distinct location and reason.
- Result: `__GO.state().selftest = { running, done, total, passed, failed, failures[] }`; `__GO.selftest()` runs the suite on demand.
- `__GO` API (`core/debug.js`): `provide(key, () => jsonSafeObject)` adds a read-only section to `__GO.state()`; `expose(name, fn, usage)` adds `__GO.<name>`; names are unique (duplicates throw at boot). `__GO.help()` lists all commands with usage.
- Current state keys: `boot loop render input assets perf selftest view`. Current commands: `pause(bool) step(n) setScale(s) setPreset(name) perfReset() perfSamples() perf() selftest() loadModel(name)`; world view and test view: `teleport(x, y, z, yaw?, pitch?) setTime(hours)`; world view: `bookmark(name|index) mode(fly|walk) flatten(x, z, radius)`. Planned by SPEC: `spawnBot`, `bench`, `hitboxes`, `bookmark(name)` (A5/A6/A8/A12).

## 11. QA tooling

### tools/qa.mjs

Headless Chrome through the DevTools protocol (Node 24 built-in WebSocket/fetch, no npm packages). Temporary profile, `--headless=new --use-angle=d3d11 --enable-gpu --ignore-gpu-blocklist`, focus emulation, never a visible window; Chrome and a server it started itself are killed at the end. Dedicated workers are auto-attached, so their network requests are checked too.

```
node tools/qa.mjs --out <folder> [--url "/?view=test&autostart=1"] [--size 3840x1080] [--steps <file.json | inline JSON array>] [--timeout 300] [--flag <extra chrome flag>] [--gpu-cost] [--allow-host <host>] [--no-serve]
```

- `--url` relative URLs go to `http://localhost:8790`. If the server is not running, qa.mjs starts `server.js` and stops it afterwards (`--no-serve` disables that).
- Before loading the URL it probes WebGL2 on `about:blank`: `report.gpu = { renderer, vendor, timerQuery, hardware, maxClocksMHz }`. The run fails if the renderer is not the hardware GPU through ANGLE (SwiftShader, llvmpipe or Microsoft Basic Render are rejected) or if `EXT_disjoint_timer_query_webgl2` is missing.
- Steps (default: wait for `boot.ready`, wait 2 s, `view.png`, 5 s frame stats):
  - `{ "wait": seconds }`
  - `{ "until": "js expression", "timeout": seconds }` (fails fast with `boot failed: <reason>` as soon as `__GO.state().boot.error` is set, and the remaining steps are skipped)
  - `{ "eval": "js expression", "as": "name" }` (promises awaited, result stored in `report.results.name`)
  - `{ "shot": "file.png" }`
  - `{ "stats": "name", "seconds": 10 }`: `__GO.perfReset()`, wait, then read `__GO.perfSamples()` for exactly the frames of the window after their GPU timer results arrived (up to 4 s drain). Reports CPU ms per frame (rAF callback), GPU ms per frame (timer queries), frame interval, n/mean/p50/p95/p99/max and a 1 ms histogram, plus `mainThreadMsPerFrame` (CDP `Performance.getMetrics` TaskDuration delta divided by frames: all main-thread work including input, DataChannel, worker messages and GC outside rAF), `gpuCoverage` (frames with a GPU sample; a problem below 90%) and `gpuState` from `nvidia-smi` sampled every 100 ms during the window (pstates, graphics and memory clocks, utilization). `gpuValid` is true only if the GPU ran at full clocks for at least 95% of the window (P0, or graphics and memory clocks both at least 85% of the board maximum; under sustained browser load this RTX 4080 driver holds P2 at 2790-2805 MHz graphics and 10801 of 11201 MHz memory, which counts as full clocks). GPU numbers with `gpuValid: false` are clock-state artifacts and must not be compared.
  - `{ "key": "KeyW", "hold": seconds }`, `{ "click": [x, y], "button": "left" }`, `{ "move": [dx, dy], "steps": 10 }` (CDP input events)
  - `{ "goto": "/?view=..." }` (next URL in the same browser), `{ "viewport": [w, h, dpr?] }` (resize)
- GPU-cost mode (`--gpu-cost`): adds `--disable-gpu-vsync --disable-frame-rate-limit`, so frames render back to back and the GPU stays at full clocks. Use it for every GPU cost comparison (presets, scales, features) and for the GPU half of the performance gate; the default vsync mode keeps light scenes at low clocks and inflates their GPU times 4-6x. In GPU-cost mode the GPU queue runs deep, so CPU per-frame numbers include backpressure stalls; take CPU numbers from a default-mode run. `perf.js` keeps up to 1024 timer queries in flight so every frame is measured. Reference (A1 test scene, High, 3840x1080, three runs in qa/A1/fix1/gpu_cost_a..c): GPU p50 0.35-0.38 / 1.15 / 5.08-5.10 ms at scale 0.5 / 1 / 2, scale 1 agrees within 1% between runs; presets Medium / High / Ultra 1.03 / 1.14 / 3.49 ms.
- Output: `<out>/report.json` (url, chrome version, flags, gpu, viewport, console messages with level and source location, page errors, failed requests, foreign requests, attached workers, step results and timings, stats, screenshots, problems, ok) and the PNGs. Exit code 0 only if there is no console error, warning or failed `console.assert`, no page error, no failed request, no request to a host outside localhost/127.0.0.1/[::1] (plus `--allow-host` hosts; WebSockets included) and no problem.
- Known headless limits: Chrome refuses pointer lock in headless mode (`WrongDocumentError`), so the raw-mouse path is covered by code review and the selftest of the lock gate; keys, clicks and everything else run through the real input path. The first seconds after launch run with low GPU clocks: warm up (wait or a first stats window) before measuring. In Git Bash quote URLs with a query (`"/?view=test"`); a bare `/` is rewritten to a Windows path by MSYS.

Examples:

### tools/check.mjs

`node tools/check.mjs`: syntax of every script (`node --check`), every static and dynamic import in `src/` resolves (relative or through the import map), every named import exists in the target module (vendored bundles included), import map targets and `index.html` references exist, no comments in JS/CSS/HTML/BAT (template-string GLSL included), no emojis in code or docs, and a scope analysis of every own script parsed with acorn: undefined identifiers (against the browser globals for `src/`, the Node globals for `tools/` and `server.js`), `let`/`const`/`class` bindings used before their declaration in the same function, and direct calls with more arguments than the called own function declares (local functions and named imports from own modules). Prints one OK line or one line per problem (`file:line reason`) and exits 1.

### tools/vendor.mjs

`node tools/vendor.mjs` downloads the pinned tarballs from registry.npmjs.org, verifies the registry integrity hash, copies each entry file plus its static relative import closure (and referenced source maps) into `vendor/<package>/`, and rewrites `vendor/VERSIONS.txt`. To add a three.js addon (for example `examples/jsm/utils/SkeletonUtils.js`) add it to the entries and rerun. New packages also need an import map entry in `index.html` (unless they are tools-only) and a reason in section 12.

### Workflow per section

1. `node tools/check.mjs` after every section.
2. `node tools/qa.mjs --url "/?view=<view>&autostart=1&selftest=1" ...` must end with `qa: OK` and `selftest.failed === 0`; `__GO.selftest()` run again afterwards must also give `failed === 0`.
3. Screenshots at 3840x1080 (and 1920x1080 via `viewport` for UI work) are inspected with the Read tool.
4. GPU cost comparisons use `--gpu-cost` and only `gpuValid` windows.
5. Output goes to `qa/<aspect>/builder|fix<k>|round<k>/`.

## 12. Libraries and decisions

- three 0.186.1 (WebGLRenderer, WebGL2 only), addons: GLTFLoader, DRACOLoader, KTX2Loader, meshopt decoder, Sky, SunLight (its shadow replaced by our `CascadedShadow`, section 7; three's own `SunLightShadow` is fixed at 2 cascades, which cannot be both sharp near the player and reach 300 m at 127 deg FOV), Pass (needed by n8ao). three-mesh-bvh 0.9.15 (all raycasts from A5 on). postprocessing 6.39.5 + n8ao 2.0.1 (post chain). peerjs 1.5.5 (the npm package's self-contained `dist/peerjs.min.js`, loaded with `await import('peerjs')` which defines `window.peerjs`). acorn 8.18.0 (MIT, tools only: the scope analysis of tools/check.mjs; not in the import map, never loaded by the page).
- recast-navigation and rapier are not vendored. Character movement is a capsule against the three-mesh-bvh world (A7), grenade bounces are sphere/ray casts against the same BVH, and bot navigation can use a baked grid or navmesh (A5/A8). A builder who needs either library adds it with tools/vendor.mjs and writes the reason here.
- Reversed float depth (section 7). N8AO 2.0.1 detects it by itself; its final copy quad has depth testing on by default, which rejects every pixel against the reversed depth buffer, so `post.js` turns that test off (checked by a selftest that reads back the canvas).
- Tone mapping is done by the post chain (`ToneMappingEffect`; S2 switched ACES filmic to Khronos PBR Neutral because ACES shifted the saturated greens and blues of the lush map toward yellow and cyan, AgX had already been rejected as washed out), so `renderer.toneMapping` stays `NoToneMapping`; exposure is `renderer.toneMappingExposure` (set by the view/lighting; three's ACES applies `exposure / 0.6`).
- Anti-aliasing: SMAA (high) as the last pass with dithering; A6 adds specular AA and a temporal AA in the same slot (section 7).
- `renderer.debug.checkShaderErrors = false` (three's production recommendation; with it on, the D3D11 HLSL compiler prints benign notes such as X4122/X3595 for three's PMREM and N8AO shaders as console warnings). Real shader failures are still reported: `render.verifyPrograms()` checks `LINK_STATUS` of every new program once after compilation (parallel compile aware) and reports `[render] ... shader program failed to link: <name>: <logs>`; it runs after boot and every 120 frames.
- `renderer.info.autoReset = false`, reset once per frame, so `__GO.state().render.calls/triangles` are whole-frame numbers including shadow and post passes.
